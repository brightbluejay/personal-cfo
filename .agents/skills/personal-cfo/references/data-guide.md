# Fictional data guide

All committed data must be invented for demonstration and testing.

## Dates

Use ISO dates: `YYYY-MM-DD`.

## Money

Use plain decimal GBP values, for example `125.50`.

## Transaction direction

- negative amount: spending or payment;
- positive amount: income, refund, or credit.

## Debt types

Examples: `overdraft`, `credit_card`, `personal_loan`, `retail_finance`.

## Data quality

- `confirmed`: known from the local ledger;
- `estimated`: explicit user estimate;
- `unknown`: excluded from firm affordability claims.

Do not include account numbers, card numbers, passwords, PINs, security answers, tokens, or real statement text.
